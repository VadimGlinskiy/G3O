### 3.3 Статическая проверка (стат.)

- `gCInfo_PS::Read` (`Game.dll+0x1C7090`, 0x1175 байт): 6 вызовов `GetWord` подряд (`0x1C8042…0x1C8166`, шаг 0x3B), 14 вызовов `CountWords`, строковый литерал `';'`. Но 757 863 не делится на 6, значит число вызовов на запись не фиксировано — **шаблон вызовов не установлен**.
- `bCString::GetWord(int,const bCString&,bCString&,bool,bool)` (`SharedBase.dll+0x4C40`, 0x39E байт): цикл по номеру слова (`0x10004C80…0x10004ED3`); в теле на каждой итерации — поиск разделителя (`sub_1006B700`), выделение через `bCMemoryAdmin::Malloc`, копирование (`sub_10078780`), `SetText`, освобождение. Точная семантика продвижения по строке полностью не прослежена; это нужно для 8.4/8.7.
- `LoadInfosFromInis` (`+0x1CF160`): `eCArchiveManager::FindFiles`, `AddDirToCache`/`RemoveDirFromCache` в `eCVirtualFileSystem`, затем `gCInfo_PS::Read` на файл. Ни один из этих вызовов не измерен — это источник 598 мс excl.
- `gCInfoManager_PS::Read`: проверяет `IsCompiledProjectFolder`, вызывает `ReadCompiledInfoManager` (в прогоне вернул за 0.005 мс, дальше выполнился `LoadInfosFromInis`), `WriteCompiledInfoManager` не вызван. Почему скомпилированный путь не сработал, не установлено. Примечание: проектное правило `context.txt` запрещает G3O создавать собственные кэши; решение о любом использовании этого пути — только по отдельному указанию.
